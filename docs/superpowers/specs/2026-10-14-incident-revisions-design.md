# Incident corrections and withdrawals

## Intent and authorization

Journalists need to correct or withdraw an exported incident without silently replacing its history. The owner approved stable IDs, immutable publication snapshots, private correction drafts, renewed review, exact sanitized preview, explicit approval, and withdrawal notices, then expressly requested implementation on 2026-10-13 America/Toronto. That instruction authorizes execution of this specification and its plan without repeating planning approval questions. Prior subagent-driven execution preference is retained.

## Publication boundary

Local export means ready for manual public-data staging, not proof of live deployment. The existing static Pages architecture and human publication gate remain. A revision changes the local approved snapshot; a subsequent explicit export and reviewed public data merge deploy it. UI copy must say this. No source text is processed; all test content is synthetic. Telegram publication stays separate.

## Persistence and compatibility

Add migration 0007 (after candidate review 0006). `IncidentPublication` has unique incident_id, version >=1, current sanitized record. `IncidentPublicationRevision` stores immutable versioned sanitized records, action (published/corrected/withdrawn), bilingual reason, timestamp, and unique (incident_id, version). `IncidentCorrectionDraft` has incident_id primary key, base_version, complete fields, review, bilingual reason and updated_at. `IncidentWithdrawalPreview` stores incident_id, base_version, hash, exact sanitized record, bilingual reason, expiry (15 minutes). Store only local records; private snapshots retain history, public history never contains previous full claims.

The first validated explicit export attempt durably creates snapshot/revision version 1 before writing the private pending file. A file-write failure retains that approved snapshot for explicit retry. Repeated exports return the identical latest approved snapshot; preview/export must never rebuild a corrected or withdrawn record as published. Legacy approved incidents obtain a snapshot only through explicit export. Existing normal incident editing remains locked after approval. Initial snapshot creation and revision approval are serialized by an app-scoped publication lock and version checks; database unique constraints protect versions. Run one local API process, as for Telegram. Build/validate and commit snapshot changes transactionally. If pending file writing fails, remove that incident's stale export, report a generic recoverable error, retain the approved database snapshot, and require explicit export retry. No private paths in errors.

## API contract

All routes use existing localhost, origin, and CSRF protections. Unknown keys are rejected, reasons are trimmed non-empty bilingual text of at most 1000 characters. expected_version is a strict positive integer. No route changes evidence or processes its text.

- GET `/incidents/{id}/publication`: `{version, record, history, draft}`; when no export yet `{version:0,record:null,history:[],draft:null}`. Missing incident 404. History contains version/action/reason/created_at and sanitized record only, never private fields/evidence text. Draft contains base_version/fields/review/reason_en/reason_ar.
- PUT `/incidents/{id}/correction`: `{expected_version,fields:<existing IncidentEdit>,reason_en,reason_ar}`. Requires existing active publication. Create/replace a draft copied from submitted complete fields; resets review, invalidates withdrawal preview. Does not mutate current incident/publication. Reject stale version, withdrawn publication, missing snapshot, or no public change. Private governorate changes alone do not qualify as corrections.
- POST `/incidents/{id}/correction/review`: existing ReviewInput plus expected_version. Stores review for the matching draft; time changes invalidate prior preview hashes. No approval shortcut.
- GET `/incidents/{id}/correction/preview`: `{record,preview_hash,version}`. Build against a detached approved Incident with draft fields/review and original ID/evidence references, using the full existing publication gate. record.status is corrected; stable ID; all public changed fields are computed from actual public projection differences, excluding updatedAt/status/corrections. Append `{correctedAt,reason:{en,ar},changedFields}` to previous public corrections. updatedAt uses draft updated_at, making hash stable until edit/review/version change. Reject no public diff and incomplete safety review.
- POST `/incidents/{id}/correction/approve`: `{expected_version,preview_hash,acknowledged:true}`. Rebuild and compare exact digest, reject stale/tampered/unreviewed input, append next immutable snapshot/revision, update original incident fields/review to accepted draft, remove draft/previews, append audit. Remove the previous per-incident pending export after approval so stale approved output cannot be staged accidentally. A cleanup failure retains the durable approved snapshot and reports a generic recoverable error; operator cleanup/export retry is required. No new file output or deployment.
- POST `/incidents/{id}/withdrawal/preview`: `{expected_version,reason_en,reason_ar}`. Requires current published/corrected snapshot. Stores exact tombstone and digest with 15-minute expiry; returns `{record,preview_hash,version}`. Does not mutate approved snapshot. Replaces earlier preview for same incident.
- POST `/incidents/{id}/withdrawal/approve`: same approval payload. Verify latest version, hash, unexpired preview and acknowledgment. Append withdrawal snapshot/revision; mark incident withdrawn, clear draft/previews, append audit. Invalidate the previous pending export after durable approval, with the same recoverable cleanup behavior as correction approval. Withdrawal is terminal in this slice. Never automatically restore or republish.

Use existing deterministic `digest` for snapshots and preview comparison. Every material edit/review/approval/export emits audit hashes; reject actions leave snapshots/history untouched. Normal `/preview` and `/export` use the latest snapshot when one exists. Corrections require review and acknowledgment independently of channel/source approval.

## Public withdrawal record

Retain current public schema 1.0.0. A withdrawal record has original ID, status withdrawn, updatedAt and occurredAt set to withdrawal time, confidence unverified, original category identifiers, generic bilingual title `Withdrawn report` / `تقرير مسحوب`, summary equal to human-written bilingual withdrawal reason, generic uncertainty `This report has been withdrawn.` / `تم سحب هذا التقرير.`, withheld location label `Withheld` / `محجوب`, precision withheld, zero sources and no coordinates. Public corrections contain only the withdrawal reason/time and changedFields including status; earlier public correction reasons are suppressed in the tombstone to avoid repeating withdrawn material. Full previous sanitized snapshots/reasons remain private. This preserves traceability without continuing to expose the old headline, summary, links, or location.

Public feed and details prominently show withdrawn status/reason/time; no confidence badge or old source links for withdrawn records. Withdrawn records remain discoverable in the feed but are excluded from active summary cards, map, and activity timeline. Search does not inspect previous private snapshots. Corrected records retain normal presentation and visible correction reason, timestamp and changedFields. English/Arabic and RTL are mandatory.

## Analyst flow

Add an incident publication section/page reachable from the existing case page. Show local export version and complete revision history. For an exported active incident, render a complete correction editor (same controlled fields as existing editor, no evidence editing), bilingual reasons, review checklist, exact preview, then explicit approval. Any draft edit resets review. For withdrawal, enter bilingual reason, inspect generic tombstone, then approve. Approval controls carry server-returned version/hash, never invented values. After approval show local-only status and offer existing explicit export. Render API errors safely with no raw error/path/body echo. Approved historical versions remain read-only; withdrawn cases offer no correction/restore controls.

## Verification and limits

API tests cover first/repeated exports; real public-diff classification; draft isolation; review reset; complete gate; stale hashes/versions; forbidden fields; missing/legacy cases; repeated withdrawal; preview expiry; audit/immutable history; export failure/retry; serialization and DB uniqueness; private governorate excluded throughout. Migration tests cover upgrading existing populated database. Browser tests use synthetic initial export, correction, new approval/export, withdrawal/export and public preview. Public unit/browser tests prove withdrawn claims cannot remain on map/timeline/active counts/details. Full API/JS suites, policy, lint, typecheck, builds and CI remain required.

No remote multi-user editing, rollback/restoration, evidence replacement, raw-text processing, automated publication, new dependencies, or live account tests in this slice. Manual Git staging follows the existing architecture and must preserve other incident records; document merge-by-ID and schema validation, not replacing the entire dataset with one exported incident.
